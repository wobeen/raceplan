# 구제 경로 검증 여유 상향 개발 비교 — 사전 등록 (2026-11-25, 정책 v2)

## 착수와 범위

사용자 지시(2026-11-25): "1번 가설로 진행하고 정책 v2는 이 브랜치에서 계속 시험해".
1번 가설은 [직전 스텝](LEADIN_RESCUE_DEVELOPMENT.md)의 결론인 "경로 검증 여유를 추종 오차 이상으로
둔다"이다. 브랜치 `research/policy-v2-curvature`에서 정책 v2 절차를 따른다(사전 등록 → 독립 검토
→ 1회 실행 → 결과 커밋). 이 스텝은 **개발 선택**이며 held-out 근거가 아니다.

## 가설과 파라미터 고정 근거

직전 스텝의 구제 경로는 footprint 여유 0.030–0.048m, 추종 RMSE 0.034–0.047m였고 9개 episode가
모두 충돌했다. 새 입력을 만들기 전에 직전 실행(노출 자료)에서 도달한 `smoothed_low_clearance`
36 episode의 **최대 추종 오차**를 집계했다(`results/margin_parameter_basis.py`; 원자료는 Git 제외
로컬 raw라 저장소만으로는 재현되지 않는다).

| 묶음 | episode | 최소 | 중앙값 | P90 | 최대 |
|---|---:|---:|---:|---:|---:|
| 전체 | 36 | 0.020 | 0.076 | 0.102 | 0.113 |
| 경로 시작 오프셋 0m (turn_aware) | 18 | 0.020 | 0.038 | 0.063 | 0.065 |
| 경로 시작 오프셋 0.141m (smoothing held-out) | 18 | 0.087 | 0.100 | 0.107 | 0.113 |

A* 경로는 시작 셀 중심에서 시작한다. 그래서 최대 추종 오차는 출발점과 경로 시작점의 오프셋에 크게
좌우된다. 0.08m는 두 군집 사이 값이고 0.11m는 오프셋이 있는 군집의 최댓값 근처다. 새 입력의
시작점 (1.2, 0.1m 단위 y)도 셀 중심과 0.1–0.141m 어긋난다. 따라서 0.11m가 이번 입력의 예상
최대 오차에 해당하고, 0.08m는 그보다 작다. 두 값 모두 새 입력을 보기 전에 정했다.

## 후보 (1차 검토로 재설계)

1차 검토 P1에 따라 여유 상향을 **구제 단계에만** 적용한다. 처음 등록한 설계(모든 검증의 여유 상향)는
기존 채택 경로를 거부해 raw A*로 되돌리게 했다. 노출 자료로 대입하면 손실이 4–5 query로 예측됐다.

| 이름 | 역할 | 내용 |
|---|---|---|
| `margin_rescue_08` | 후보 | 기존 후보(여유 0.02m)가 채택하면 그대로 반환하고, 거부하면 lead-in 구제의 모든 검증(평활화 재검사, 호, 이어 붙인 경로)을 여유 0.08m로 한다 |
| `margin_rescue_11` | 후보 | 같은 구조, 여유 0.11m |
| `leadin_rescue_k3` | ablation(여유 0.02m 구제), 선택 불가 | 직전 스텝 후보 |
| `smoothed_low_clearance` | 기준 | 여유 0.02m 후처리 |

구현은 `examples/margin_rescue_planner.py`다. 커밋된 `leadin_rescue_planner.py`와
`smoothed_astar_planner.py`를 내용 hash로 불러오며 두 파일은 수정하지 않는다.

결과가 기준과 달라질 수 있는 곳은 기존 후보가 거부한 query뿐이다. 회귀 검정 층은 "기존 후보 거부 ∧
raw A* 경로로 도달"한 query다. 구제가 끝나기 전에 시간이 다 되면 기존 결과를 반환한다.

## 새 개발 입력 (절차 생성)

이번 가설은 직전 20 query에서 나왔으므로 그 입력은 다시 쓰지 않는다. runner의 `generate`가 커밋된
seed **1000–1011**로 실행할 때 지도 12개와 query 24개를 만든다.

- 지도는 10.4×7.2m, 해상도 0.2m, 0.2m 외벽이다. family는 seed 순서대로 staggered_windows,
  offset_islands, slalom_walls를 4개씩 돈다. 장애물 범위는 `interior`에 있다.
- query는 지도마다 두 개다. (1.2, y)→(9.2, y′)이고, y는 [1.4, 1.8]과 [5.4, 5.8]에서 0.1m 단위로
  뽑는다. 시작·목표의 footprint clearance가 둘 다 **0.15m 이상**이 될 때까지 같은 난수열로 다시
  뽑는다(최대 50회, 실패하면 오류).
- seed 2000 이상은 held-out용으로 예약하며, 생성기가 거부한다. 테스트 smoke는 seed 1999만 쓰며,
  이 seed는 소진된 것으로 기록한다.
- 신규성은 세 가지를 본다. Git에 커밋된 지도·시나리오와의 exact v2 identity, 같은 격자 크기에서의
  점유 셀 IoU, 생성된 지도끼리의 IoU다. exact 중복이 있거나 IoU가 0.9 이상이면 실행을 거부한다.
  지도 exact 거부로 `results/README.md`의 "같은 지도 0.5m query" 조항도 충족한다. 사전 등록
  테스트는 지도를 생성만 하고(계획·주행 없음) 중복 0, IoU 0.9 미만, 끝점 여유 0.15m 이상을 확인한다.
- 생성 입력은 `results/analysis`에 커밋하지 않는다. 생성기로 재현되고, 커밋하면 다음 신규성 검사의
  자기 사본이 되기 때문이다. 공유 사본에는 novelty·protocol·decision·집계만 둔다.

해석 제한: 생성기 범위는 노출된 smoothing held-out 지도 설계와 시작·목표 배치를 중심으로 흩뜨린
것이다. 외벽 셀이 IoU를 채우므로 0.9 기준은 약한 근사 중복 검사다. 결과는 같은 family 형상의
개발 근거로만 읽는다.

## 실행

seed는 11/12/13이고 잡음은 이전과 같다. planner는 A*, Hybrid A*, 기준, ablation, 후보 2개로
24 query × 3 seed × 6 = 432 episode다.

- runner는 추적 파일이 dirty이거나 사전 등록 커밋이 HEAD의 조상이 아니면 거부한다.
- 계획 전에 `novelty.json`과 `protocol_start.json`을 쓴다. 기록 항목은 실행 커밋, `uv.lock` hash,
  Python·OS, import 경로, 출력 폴더 기준 입력 hash다.
- 실행 후 후처리 planner 4개를 결정적으로 재계획해 저장 경로와 pose 단위로 비교한다. 하나라도
  다르면 `invalid_audit`다.
- 도중 예외가 나면 `aborted.json`을 남기고 이 스텝에서 재실행하지 않는다.
- 다른 무거운 작업이 없을 때 실행한다(구제 timeout은 벽시계에 의존한다).

```powershell
$env:PYTHONPATH = (Resolve-Path src).Path
.venv/Scripts/python.exe results/margin_rescue_development.py `
  --output-dir results/raw/margin_rescue_development_20261125 --prereg-commit <사전 등록 커밋>
```

## 판정 규칙 (runner의 `decide`)

- **분석 단위**: query이며, 3 seed 중 2개 이상 도달하면 도달로 본다.
- **효과 분모와 층**: 기존 후보가 거부한 query가 분모다. 이것이 4개 미만이면 "판단 불가"다.
- **무회귀**: 기준이나 A*가 도달한 query를 하나도 잃지 않아야 한다. "거부 ∧ raw A* 경로 도달"
  query가 2개 미만이면 무회귀 근거는 `untestable`이고, 선택 결과에 "순증만으로 선택, 회귀 검정
  불가"를 붙인다. 이 표시는 정책 템플릿("층 최소치 미달 → 판단 불가")에서 벗어난 것이다. 직전 스텝과
  같은 근거(구제형 후보는 무회귀 층이 구조상 작다)를 따른다.
- **최소 효과**: 기준 대비 query 순증 ≥ max(2, ⌈0.25 × 거부 query 수⌉).
- **선택 순서**: 순증 → 구제 후 도달 query 수 → 계획시간 P95 → 작은 여유(0.08).
- **판정별 후속**: 선택됨 → 중단하고, seed 2000 이상 held-out(거부 ∧ A* 경로 도달 query 포함)은
  사용자 승인 후 진행한다. 선택 없음 → 음성으로 기록하고 이 입력에서 더 조정하지 않는다.
  판단 불가·감사 무효·중단 → 기록만 하고 재실행하지 않는다.
- ablation, Hybrid A*, seed 단위 수치는 보조로만 보고한다. 순증에는 "기준이 망친 query를
  ablation이 되살린 경우"가 섞이지 않는다. 후보는 기준 채택 경로를 바꾸지 않기 때문이다.

1차: `anthropic/claude-fable-5-2`가 사전 등록 `41610c3`를 검토했고, 판정은 "수정 후 재검토"였다.

  - 판단 불가 상한과 기전별 집계(구제·구제 후 도달)를 decision에 추가했다.

  - 생성 지도끼리의 IoU 검사를 추가했다. 입력을 커밋하지 않는다고 명시했다.
  - 끝점 여유 0.15m를 생성 조건으로 넣고 기록하게 했다.
  - HANDOFF에 착수 승인을 기록했다.
  - 중단 시 `aborted.json`을 쓰고 재실행하지 않는다.
- **P3**:
  - 죽은 설정 필드를 없앴다. 새 설정 `MarginRescueConfig`의 여유는 실제로 쓰인다.
  - 빈 인벤토리에서의 `max` 오류를 고쳤다.
  - 신규성 양성 경로, 순증 경계, 동률, "기준 채택 경로 유지" 기전 테스트를 추가했다.
  - 입력 hash 키는 출력 폴더 기준으로 둔다(입력이 실행 시 생성되므로).

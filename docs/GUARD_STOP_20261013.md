# 장애물 제어 정지 원인 분석

저장된 validation 결과의 guard timeout 18건을 분석했다. 재주행이나 새로운 평가가 아니다.
성공 기준은 충돌 없이 목표 위치 0.5m 이내 도달이다.

- 18건 모두 최종 상태의 차체 여유 기반 속도 상한이 0이었다.
- 9건은 마지막 적용 조향을 1m 유지하면 충돌이 예측됐다.
- 나머지 9건은 그 예측 구간에서 충돌이 없었다.
- 전방 제동 상한은 18건 모두 양수였다. 즉 최종 순간의 정지는 측면 제한이 결정했다.

이는 전체 정지 과정의 인과 증명이나 측면 제한 해제의 안전 보장이 아니다.
최종 자세와 마지막 조향의 진단이며, 향후 조향 변화와 샘플 사이 충돌은 보장하지 않는다.
기존 제어를 바꾸지 않고 `guard_diagnostics`로 진단값을 분리했다.
평행 벽과 전방 벽의 구분 테스트를 추가했고 전체 73개 테스트가 통과했다.

다음 구현은 이 두 경우를 구분하는 재출발 정책과 필요 시 재계획이다.
측면 제한만 제거한 정책도 같은 저장 경로·seed로 비교하고 충돌/도달/timeout을 모두 보고해야 한다.

실행: `.venv/Scripts/python.exe results/guard_stop_analysis.py`
원본: `results/analysis/obstacle_guard_20261013/` (로컬 trajectories.json 필요)
출력: `results/analysis/guard_stop_20261013/`, `results/figures/guard_stop_20261013.png`
이 스크립트는 원본을 보존하고 파생 분석 출력만 재생성한다. 입력 hash를 manifest에 기록한다.

파일 정리에서는 재생성 가능한 pytest 임시 산출물과 Python 캐시만 제거했다.
실험 원본, 재현 ZIP, 과거 결과, 가상환경과 런타임은 유지했다.

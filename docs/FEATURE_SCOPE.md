## 승격 기준 (2026-11-24, 정책 v2 시험 브랜치)

연구 후보는 연구 보관 → 권장 예제 → 내장 planner 순서로만 승격한다. 권장 예제 이상은
아래를 모두 만족해야 한다.

- 서로 독립인 사전 봉인 held-out을 2회 이상 통과한다. 각 평가는 24 query 이상이고,
  기준 planner(A*)가 성공하는 query가 30% 이상 포함된다.
- query 단위로 A* 성공 query에서 패배 0, 전체 도달률 순증 +25%p 이상이다.
- Hybrid A* 대비 query 단위 net ≥ 0이다.
- 후처리형 후보는 채택률 75% 이상이다. 계획시간 P95는 계획 timeout의 25% 이하다.
- 독립 검토 승인과 결과 커밋 시점의 전체 pytest 통과 기록이 있다.

내장 planner 승격은 위에 더해 기본 CLI·GUI·문서 영향 검토를 별도 기능 스텝으로 진행한다.

## 판정 규칙 템플릿

모든 개발 선택·held-out 판정 규칙은 실행 전에 다음 항목을 문서와 runner에 함께 적는다.

- **분석 단위**: query. 같은 query의 seed는 독립 표본이 아니다. query 결과는 seed 과반
  도달 여부이며, seed 단위 수치는 보조로만 보고한다.
- **비교 기준과 층**: 무회귀를 볼 기준 planner와, 그 planner가 성공한 query 수의 최소치.
  최소치에 못 미치면 판정은 "판단 불가"다.
- **최소 효과크기**: 순증 query 수 또는 비율의 하한.
- **선택 순서**: 실제로 적용할 순서 그대로(예: 패배 0 → 순증 → 채택률 → 계획시간).
- **판정별 후속**: 통과·불통과·판단 불가 각각에서 다음 행동.

## 연구 코드의 보존 이유

실행 소스와 경로가 기존 protocol/seal의 hash 검증 대상이다. 파일 이동·삭제나
코드 축소는 봉인된 결과의 재현 확인을 깨뜨릴 수 있다. 현재 정리에서는 실행 코드를
변경하지 않고, 검증된 기본 동작과 연구 기록을 유지했다.

이전에 생성한 raw 데이터·PPTX·중간 결과는 사용자 자료로 유지했다.
기능을 물리적으로 삭제하는 후속 작업에는 재현 자료를 포함한 별도 보관 방식이 필요하다.

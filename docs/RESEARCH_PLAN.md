# RacePlan 연구·개발 계획

> 개정일: 2026-10-12
> 주제: 자동차형 로봇의 경로계획, 경로 기하, 지도 난이도와 폐루프 주행 성능의 관계

## 1. 최종 목표

RacePlan은 Dijkstra, A*, Hybrid A*를 단순히 순위화하는 프로젝트가 아니다.
동일한 지도·차량·추종기·PID 조건에서 planner가 만든 경로의 차이가 실제 주행의
도달률, 충돌, 추종 오차와 조향 안정성에 어떻게 연결되는지 분석한다.

그 결과를 바탕으로 지도 난이도와 경로 특성에 따라 비용 가중치 또는 planner를
선택하는 방법을 설계하고, 튜닝에 사용하지 않은 지도에서도 개선이 유지되는지
검증한다.

핵심 연구 질문은 다음과 같다.

> 차량 크기로 정규화한 지도 난이도와 계획 경로의 기하 특성이 고정 controller의
> 폐루프 실패를 얼마나 설명하며, 조건부 planner 또는 비용 선택 규칙이 미사용
> 지도에서 안전성과 추종성을 개선할 수 있는가?

CV 인식, SLAM, 실차, 부분 미지 환경은 이 핵심 연구가 끝난 뒤의 확장으로 둔다.
ROS 2는 재현과 통합을 위한 수단이며 단독 연구 기여로 주장하지 않는다.

## 2. 연구 질문

| 질문 | 확인할 내용 | 주요 지표 |
|---|---|---|
| RQ1 | 같은 격자 조건에서 A*가 Dijkstra의 최적 비용을 유지하며 탐색량을 줄이는가? | 경로 비용, 탐색 노드, 계획 시간 |
| RQ2 | 자동차 운동학을 반영한 경로가 고정 controller에서 더 잘 추종되는가? | 도달률, 충돌률, RMSE, 조향 포화 |
| RQ3 | 어떤 지도·시작·목표 조건이 planner별 실패를 만드는가? | 병목 폭, 장애물 밀도, 우회도, 요구 곡률, 실패 유형 |
| RQ4 | 길이·곡률·조향 변화·안전성 비용 사이에 어떤 교환관계가 있는가? | Pareto 관계, clearance, 곡률, 경로 길이, 계산량 |
| RQ5 | 검증 지도에서 정한 조건부 선택 규칙이 미사용 지도에도 일반화되는가? | 성공률, 효과크기, 최악 분위수, 계산비용 |

새 알고리즘의 발명을 미리 전제하지 않는다. 증거에 따라 `개선 변형`,
`조건부 선택 방법`, `새 알고리즘 후보` 중 적절한 수준으로 결과를 표현한다.
선행연구와 연구 공백은 [LITERATURE_GAP.md](LITERATURE_GAP.md)에 관리한다.

## 3. 진행 방식: 세 트랙

세부 기능별 일정을 나열하는 대신 개발, 실험, 연구·분석의 세 트랙을 반복해서
진행한다. 재현성은 연구 결론 자체가 아니라 공정한 비교와 검증 가능한 결론을
만드는 공통 기반으로 둔다.

```text
개발 → 재현 가능한 실험 → 연구·분석 → 다음 개발·실험 설계로 환류
```

### 개발 트랙

실험을 가능하게 하고 연구 가설을 코드로 표현하는 트랙이다.

| 묶음 | 내용 | 상태 |
|---|---|---|
| Baseline planner | Dijkstra, A*, Hybrid A*, 공통 결과 형식 | 완료 |
| 공통 주행 계층 | 차량 footprint, 자전거 모델, Pure Pursuit, 속도 PID, 명령 제한 | 완료 |
| 단일 실험 파이프라인 | 계획→주행→지표→CSV | 완료 |
| 반복 실험 기반 | `map_seed`/`simulation_seed` 분리, 잡음, batch runner, trajectory 저장 | 다음 작업 |
| 평가 기능 | 지도 난이도, 경로 기하, clearance, 집계와 그래프 | 예정 |
| 개선 후보 | fixed multi-cost, complexity-conditioned cost 또는 planner selector | baseline 분석 후 결정 |
| 재현·통합 | 설정 고정, 환경 기록, 자동 재현, 필요 시 ROS 2 wrapper | 예정 |

개발 우선순위는 기능 수가 아니라 다음 실험에서 필요한 최소 기능으로 정한다.
baseline 실패 분석 전에는 개선 알고리즘을 확정하지 않는다.

### 실험 트랙

구현이 의도대로 작동하는지 확인하고 연구 질문에 대한 증거를 만드는 트랙이다.

| 구분 | 목적 | 운용 방식 | 상태 |
|---|---|---|---|
| 스모크 | 연결·저장·충돌 판정 확인 | 지도 1개, seed 1개 | 완료 |
| 파일럿 | 지표와 난이도 구간, 잡음 크기, 실행 예산 점검 | 검증 지도 2개, 소수 query/seed | 다음 작업 |
| Baseline 본 실험 | 세 planner의 계획·폐루프 실패 조건 분석 | 고정된 지도/query/seed 짝비교 | 예정 |
| 최적화 | 비용 가중치와 선택 규칙 설계 | 검증 지도에서만 탐색 | 예정 |
| 최종 평가 | 일반화와 교환관계 검증 | 미사용 평가 지도, 가중치 재조정 금지 | 예정 |
| Ablation | 개선 원인의 분리 | 비용항·지도 특성·selector 구성요소 제거 | 예정 |

현재 스모크 결과에서는 세 planner 모두 데모 목표에 충돌 없이 도달했다. 추종
RMSE는 Dijkstra 0.0865 m, A* 0.1299 m, Hybrid A* 0.0250 m였다. 이는 단일
실행 개발값이며 연구 결과로 사용하지 않는다.

### 연구·분석 트랙

실험 데이터를 해석하여 planner별 차이와 실패 조건을 밝히는 트랙이다. 단순한
성능 순위보다 어떤 조건에서 왜 결과가 달라지는지를 연구 대상으로 삼는다.

| 분석 묶음 | 확인할 내용 | 상태 |
|---|---|---|
| 계획–주행 관계 | 경로 길이·곡률·clearance가 충돌, RMSE, 조향 포화를 얼마나 설명하는가 | 지표 구현 후 진행 |
| 지도 난이도별 비교 | 장애물 밀도·병목 폭·우회도에 따라 planner 순위가 달라지는가 | baseline 실험 후 진행 |
| 실패 조건 분석 | 짧은 경로도 추종에 실패하는 조건과 planner별 구조적 실패는 무엇인가 | episode 축적 후 진행 |
| Benchmark 공백 | 기존 계획 지표가 놓치는 폐루프 실패와 필요한 추가 지표는 무엇인가 | 선행연구와 병행 |
| 신규 planner 평가 | 새 planner가 어떤 조건에서 기존 baseline보다 유효한가 | 신규 후보 추가 시 반복 |

연구 트랙에서는 평균값만으로 우열을 선언하지 않는다. 지도 특성별 계층화,
paired comparison, worst-case와 대표 실패 episode를 함께 사용한다.

## 4. 세 트랙의 연결 기준

개발 완료 여부는 코드의 존재가 아니라 대응 실험이 실행되고, 그 결과로 연구
질문을 검토할 수 있는지로 판단한다.

| 합류 지점 | 개발 산출물 | 실험 산출물 | 연구·분석 판단 |
|---|---|---|---|
| 폐루프 baseline | 공통 controller·simulator·metrics | 모든 planner의 성공과 실패를 같은 형식으로 저장 | 계획 지표와 주행 지표의 차이를 분석 가능 |
| 반복성 | seed 분리·batch runner | 같은 조건 재현, seed 대상 명시 | 우연한 변동과 planner 효과를 분리 가능 |
| 난이도 분석 | 지도·경로 특성 계산 | 난이도 구간별 paired result | 조건별 순위 변화와 실패 유형을 설명 가능 |
| 신규 planner | 공통 인터페이스와 등록 방식 | 기존 baseline과 동일 조건으로 실행 | 유효 조건, 효과크기와 한계를 비교 가능 |
| 연구 결론 | 고정 설정·분석 스크립트 | held-out 지도 결과 | 효과와 실패·한계를 함께 보고 가능 |

파일럿에서 지표가 의미 없거나 실험 조건이 불공정하면 해당 개발 항목으로
돌아간다. 최종 평가 결과를 본 뒤 가중치를 다시 조정하지 않는다.

## 5. 비교의 공정성

- 모든 planner는 같은 지도, 시작·목표, 차량 크기와 시간 제한을 사용한다.
- 모든 계획 경로는 같은 tracker, PID, 차량 모델, 제어 주기와 출력 제한으로
  추종한다.
- 격자 planner는 장애물 팽창을 사용하고 Hybrid A*는 회전된 직사각형 footprint를
  검사하므로 두 표현의 차이를 설정과 결과에 명시한다.
- 격자 goal-cell 도달과 Hybrid A* goal-pose tolerance 차이를 기록하고 최종 위치
  오차를 별도 보고한다.
- 서로 다른 waypoint 간격은 공통 간격으로 재표본화한 뒤 곡률과 조향 변화를
  비교한다.
- 실패 episode를 제외한 평균만 제시하지 않는다. 실패율과 성공 episode의
  연속 지표를 함께 보고한다.

## 6. Seed와 무작위성

무작위 지도와 주행 잡음을 하나의 seed로 섞지 않는다.

- `map_seed`: 장애물 배치나 절차적 지도 생성에만 사용
- `simulation_seed`: 센서·조향·속도·초기 상태 잡음에만 사용
- deterministic planner의 시간 반복: seed 표본과 구분하여 별도 측정

같은 `map/query/simulation_seed` 조합을 모든 planner에 적용해 paired comparison을
만든다. 고정 지도 실험에서는 `map_seed` 대신 지도 파일과 hash를 기록한다.
랜덤 생성 지도는 연결 가능성, 시작·목표 유효성, 최소 통로 폭을 검사한 뒤
채택하고 탈락 이유도 기록한다.

## 7. 지도와 데이터 분리

검증 지도는 설계와 가중치 선택에 사용하고 평가 지도는 최종 확인 전까지 결과를
보지 않는다. 기본 규모는 파일럿 이후 실행 예산에 맞춰 고정한다.

- 검증 지도: 최소 2개 map family
- 평가 지도: 최소 4개, 검증과 다른 seed 또는 별도 수작업 지도
- 각 지도: 여러 시작·목표 query
- 각 query: 여러 simulation seed
- 필수 구조: 열린 공간, 장애물 밀집, 좁은 통로, 급커브, 목표 방향 제약

지도 난이도는 `simple/complex` 같은 이름만 사용하지 않고 다음 값으로 표현한다.

- obstacle density
- minimum bottleneck width / vehicle width
- reference-path length / straight-line distance
- heading change 또는 required curvature
- goal-heading constraint와 dead-end 구조

## 8. 평가 기준

평가는 하나의 가중 평균으로 모든 결과를 숨기지 않고 다음 순서로 해석한다.

1. 안전·성공: collision-free reach rate, timeout rate
2. 추종: RMSE / vehicle width, 최대 오차, 조향 포화율
3. 경로 품질: 길이, 최소 clearance / vehicle width, 곡률, 조향 변화
4. 계산량: 계획시간 중앙값·95분위수, 탐색 노드, timeout

같은 map/query/seed를 짝지어 비교하고 median, IQR, confidence interval,
효과크기를 보고한다. 평균 외에도 worst 10%, map family별 결과와 대표 실패 사례를
제시한다. 시간 측정은 한 환경에서 GUI와 병렬 작업을 끄고 예열 후 수행한다.

## 9. 다음 작업 묶음

다음 중간 점검까지 세 트랙에서 아래 범위만 진행한다.

### 개발

- scenario에 `map_seed`와 `simulation_seed` 의미를 분리
- 재현 가능한 초기 상태·조향·속도 잡음 모델 추가
- 여러 planner와 seed를 실행하는 batch runner 추가
- episode 요약 CSV와 trajectory CSV 분리 저장

### 실험

- 현재 demo와 추가 소형 지도에서 무잡음 회귀 확인
- 동일 seed가 동일 trajectory를 만드는지 확인
- 서로 다른 simulation seed가 planner가 아니라 주행에만 영향을 주는지 확인
- 소수 seed 파일럿으로 잡음 크기와 실행시간 결정

### 연구·분석

- 계획 결과와 폐루프 결과를 연결할 분석 단위를 확정
- 경로 길이, 추종 RMSE, 충돌처럼 현재 저장 가능한 지표의 관계를 파일럿으로 확인
- 추가로 필요한 경로 기하·지도 난이도 지표를 정의
- 성공 여부뿐 아니라 대표 실패 episode를 보존하는 분류 기준 마련

이 묶음이 끝난 뒤 지도 복잡도 지표 구현과 baseline 실험 규모를 확정한다.

## 10. 완료 기준

- 세 planner의 계획 및 동일-controller 폐루프 결과가 자동 저장된다.
- 지도·query·seed와 환경 정보가 결과에서 추적 가능하다.
- 평가 지도 4개 이상에서 baseline과 개선 후보를 비교한다.
- 비용함수 탐색은 validation에서만 수행하고 held-out 평가를 유지한다.
- 최소 한 개 개선 후보에 대해 baseline 및 ablation 결과를 남긴다.
- 성공률뿐 아니라 실패 사례, worst-case, 계산비용과 음성 결과를 공개한다.
- 한 명령으로 설정→실험→CSV→표·그래프를 재현한다.
- README, 라이선스, 인용 정보와 실행 환경을 정리한다.

개선 후보가 baseline을 이기지 못하면 신규성을 과장하지 않고 실패 조건과 음성
결과를 연구 결과로 보고한다.

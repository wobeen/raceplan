# RacePlan 연구·개발 계획

> 작성일: 2026-10-11 · 수행: 1명 · 진행 기간: 고정 기한 없이 단계별 완료 기준에 따라 진행
> 프로젝트명: RacePlan · 저장소/폴더명: `raceplan`
> 제목: F1TENTH 시뮬레이션 기반 전역 경로계획 알고리즘 비교 연구

## 1. 목적과 범위

자동차형 이동 로봇에서 Dijkstra, A*, Hybrid A*를 동일한 지도·차량·추종기·PID 조건으로 실행하고, 계획 성능과 실제 추종 성능의 차이 및 실패 원인을 분석한다. 비교 분석을 핵심 제출물로 삼는다. 비교 결과가 충분하면 Hybrid A* 비용함수 보완을 추가 학습·확장 연구로 진행한다. 개선 효과가 없거나 가설이 기각되어도 결과를 그대로 보고한다.

### 필수

- 알려진 2D 지도에서 세 planner 구현 및 공통 인터페이스 제공
- 동일 경로 추종기와 고정 PID를 사용한 차량 주행
- 자동 반복 실험, 계획·주행 지표 계산, CSV 저장
- 알고리즘별 실패 사례 분석과 통계·그래프 생성
- 재현 명령, 테스트, README, 라이선스, 보고서, 시연 영상

### 조건부 확장

1. 비교 완료 후 장애물 여유거리·곡률·조향 변화 비용을 추가한 Hybrid A* 분석 및 ablation
2. 1차 결과가 충분할 때 LiDAR로 부분 지도를 갱신하고 장애물 발견 시 재계획
3. 여유가 있을 때 PID 게인 ×0.8/×1.0/×1.2 민감도 분석
4. ROS 2 Jazzy wrapper와 RViz 시각화

모방학습·ACT, 실기 차량, 완전한 SLAM은 후속 연구로 둔다.

## 2. 연구 질문

| 질문 | 가설 | 판단 지표 |
|---|---|---|
| RQ1: Dijkstra와 A*의 탐색 성능은 어떻게 다른가? | 같은 격자·비용·휴리스틱 조건에서 A*는 Dijkstra와 같은 최적 비용을 얻으면서 탐색량을 줄일 수 있다. | 경로 비용, 노드 수, 계획 시간 |
| RQ2: 기구학 제약 반영이 추종 성능에 어떤 영향을 주는가? | Hybrid A* 경로는 차량이 추종하기 쉬울 수 있으나 탐색 비용이 커질 수 있다. | 도달률, 충돌, RMSE, 곡률, 계획 시간 |
| RQ3: 어떤 지도와 시작·목표 조건에서 각 알고리즘이 실패하는가? | 급커브·좁은 통로·목표 방향 제약이 알고리즘별 차이를 드러낸다. | 실패 유형, 장애물 거리, 조향 변화, 포화 시간 |
| 확장 RQ4: 추가 비용항은 어떤 장단점을 만드는가? | 안전거리·부드러움 향상이 경로 길이·계획 시간 증가와 교환될 수 있다. | 기본/개선 비교와 비용항 ablation |

새 알고리즘의 발명을 주장하지 않는다. 비교 조건과 구현 차이가 결과에 주는 영향을 명시한다.

## 4. 구조와 데이터 흐름

```text
raceplan/
├── src/raceplan/
│   ├── planners/       # 공통 인터페이스, Dijkstra, A*, Hybrid A*
│   ├── controllers/    # 고정 tracker, PID, 출력 제한
│   ├── simulator/      # 차량 모델, Gym adapter, 센서, 충돌
│   ├── metrics/        # 에피소드별 수치 계산
│   └── common/         # Pose, Path, grid, 설정, 좌표 변환
├── maps/               # 검증/평가 지도 및 출처·라이선스
├── scenarios/          # 지도·시작·목표·seed·시간 제한 YAML
├── experiments/        # runner, batch, 환경 메타데이터
├── analysis/           # 집계·통계·표·그래프
├── tests/              # 단위·통합·fixture
├── results/            # 원본·집계 CSV, 그림, 표
├── docs/               # 계획·설계·지표·실험 절차·한계
├── scripts/            # 환경 구축·smoke·운영
├── pyproject.toml
├── requirements.txt
├── Makefile
├── README.md
├── LICENSE
└── CITATION.cff
```

실행 흐름은 `지도 + 시나리오 → planner → 경로 → 고정 tracker/PID → simulator → metrics → CSV → analysis → 표·그래프`다. ROS wrapper는 독립 planner core를 호출한다.

## 5. 알고리즘과 비교 조건

- Dijkstra: 8-연결 격자, 대각 이동 비용 √2, 대각 corner-cutting 금지
- A*: 같은 이동 규칙·비용·충돌 조건과 유클리드 휴리스틱
- Hybrid A*: 연속 (x, y, θ), 이산 방문 인덱스, 자전거 모델 primitive, 차량 footprint 충돌 검사
- 추종기: Pure Pursuit 또는 Stanley 하나를 선정하여 고정
- PID: 시뮬레이터의 실제 명령 인터페이스에 맞는 속도/조향 루프를 정하고 동일 게인·주기·출력 제한 유지

Hybrid A*는 전진/후진과 analytic expansion을 구현 난이도와 비교 목적에 맞게 결정한다. 후진을 쓰면 방향 정보와 후진 가능한 추종기가 필요하다. 기본 경로 생성이 어려우면 전진 전용 Dubins 방식으로 축소한다.

F1TENTH Gym이 속도·조향각을 직접 받는 경우 PID가 어떤 액추에이터 모델을 제어하는지 먼저 정의한다. 계획 시 가정한 차량 모델과 주행 시 모델의 차이를 기록한다.

충돌 판정의 물리적 기준은 모든 알고리즘에서 같은 차량 크기와 여유거리다. 격자 planner의 보수적 팽창과 Hybrid A* footprint 검사 차이, 이중 팽창 여부를 문서화한다. smoothing·속도 정책·목표 자세 조건도 공통 적용하거나 차이를 명시한다. 격자 경로의 꺾임에서 곡률을 산정하는 방법과 샘플 간격을 고정한다.

## 6. 일정

고정된 주차나 마감일을 두지 않는다. 각 단계의 완료 기준을 확인한 뒤 다음 단계로 진행하며, 실제 진도와 학습 필요에 따라 조정한다.

| 단계 | 작업 | 완료 기준 |
|---|---|---|
| 1 | 관련 문헌 5~8편, VirtualBox·시뮬레이터 smoke, OCI 가능성 확인 | 같은 시나리오 실행·로그·그래프, 버전 기록 |
| 2 | 지도 로더, 좌표 변환, 차량·Path·Planner 인터페이스, YAML | 지도·차량·입출력 단위 테스트 |
| 3 | Dijkstra와 A*, 대각 이동·tie-break·실패 처리 | 두 알고리즘 최적 비용 일치 |
| 4 | Hybrid A*, primitive·휴리스틱·충돌·목표 판정 | 최소 2개 지도에서 기구학적 경로 생성 |
| 5 | 고정 tracker/PID, headless runner, 지표·CSV | 작은 시나리오의 계획→주행→CSV 자동화 |
| 6 | 기존 3종 반복 비교, 실패 분류 | 필수 비교 E1과 중간 결과표 확보 |
| 7 | 비교 보강·실패 분석, 충분하면 비용함수 확장 | 필수 연구 결과 정리 또는 개선 구현 |
| 8 | 통계·다중 지도 재실험, 확장 수행 시 ablation | 필수 결과와 재현 파이프라인 완료 |
| 9 | 재현성·한계 보강, 여유 시 부분 미지 재계획 | 평가 결과 확정, 선택 확장 결과 분리 |
| 10 | 보고서·README·영상·릴리스 | make reproduce, 공개 코드·결과·시연 |

필수 비교 분석을 먼저 완료하고, 결과와 학습 진도에 따라 확장 연구를 진행한다. 릴리스 시점은 필수 완료 기준 충족 여부로 결정한다.

## 7. 실험 설계

검증 지도 2개와 평가 지도 4개를 분리한다. 평가 지도는 트랙형과 좁은 통로/주차장형을 포함한다. 기본 후보 규모는 지도 6 × 시작·목표 5쌍 × seed 10 = 300 에피소드/planner다. 파일럿 실행 후 시간 예산에 맞게 조정하고 최종 규모를 문서화한다.

| 실험 | 대상 | 우선순위 |
|---|---|---|
| E1 | Dijkstra, A*, Hybrid A* 계획·주행 비교 | 필수 |
| E2 | 기본/비용함수 확장 Hybrid A* 비교 | 조건부 |
| E3 | 확장 비용항별 제거 실험 | E2 수행 시 필수 |
| E4 | 검증 지도에서 소규모 가중치 탐색 | 조건부 |
| E5 | 부분 미지 지도·재계획 | 조건부 |
| E6 | PID 게인 ±20% | 여유 시 |

deterministic planner는 같은 시작·목표·지도를 seed만 바꿔 반복해도 독립 경로 표본이 늘지 않는다. seed가 바꾸는 잡음·초기 조건을 명확히 정의한다. 순수 계획 시간 반복과 주행 잡음 반복을 분리한다.

평가 지표는 계획 성공률·시간·탐색량·경로 길이, 장애물 최소 거리·곡률, 주행 도달률·충돌·추종 RMSE·조향 변화·포화 시간·완료 시간이다. 실패 에피소드를 누락하지 않고 실패 비율과 성공 에피소드의 연속 지표를 함께 보고한다.

쌍체 비교는 같은 지도·시작/목표·seed를 짝짓고, 중앙값·IQR·효과크기를 보고한다. 연속 지표의 Wilcoxon 검정 적용 조건과 동일 지도 반복의 의존성을 확인한다. 성공률에는 별도의 비율 지표를 사용한다. 평가 지도를 보고 가중치를 재조정하지 않는다.

## 8. 시간 측정과 재현성

- 공식 계획 시간은 한 환경에서 측정한다. OCI가 확보되면 A1, 그렇지 않으면 VirtualBox를 사용한다.
- 로딩·거리장 등 전처리 시간과 탐색 시간을 구분하여 모두 기록하고 비교 범위를 명시한다.
- 동일 코어·내부 스레드 수·VM 자원 조건, GUI 끔, 예열 후 3회 측정 중앙값을 사용한다.
- `taskset` 및 `OMP_NUM_THREADS=1`, `OPENBLAS_NUM_THREADS=1`은 환경에 맞춰 적용한다.
- 계획 측정과 병렬 주행·영상 렌더링을 동시에 수행하지 않는다.
- host, arch, CPU, 자원, OS, Python/의존성 버전, git commit, 설정 hash, seed를 기록한다.
- 계획 시간 제한은 초기 10초로 두고, VM 성능에 따른 timeout 편향을 보고한다.
- 측정 환경 변경 시 직접 비교할 시간 데이터를 같은 환경에서 재측정한다.
- 동일 아키텍처에서 시간 외 결과 재현성을 확인하고, x86/ARM 실수 값은 허용 오차로 비교한다. 노드 수의 완전 일치는 별도 결정성 검증 후 요구한다.

## 9. 테스트와 완료 기준

단위 테스트: 좌표 변환, 지도 팽창, 막힌 지도 실패, A*/Dijkstra 비용 일치, footprint 충돌, 운동 primitive 곡률, 지표 계산.

통합 테스트: GUI 없이 작은 YAML을 실행해 CSV와 그래프 생성, 같은 입력으로 재실행한 비시간 결과 비교. 비용함수 확장을 수행하면 가중치 0과 기본 구현의 동작 일치, 단순 지도에서 비용항 동작 검증을 추가한다. 비용 가중치 증가가 모든 지도에서 안전거리를 단조 증가시킨다고 가정하지 않는다.

## 10. 위험과 축소 기준

- 환경 준비 단계에서 Gym 설치 문제가 지속되면 자체 2D 모델로 전환하며 제목·README에 실제 실험 환경을 정확히 적는다.
- Hybrid A* 기본 구현이 막히면 후진과 Reeds-Shepp를 제외하고 전진 전용으로 축소한다.
- 기존 알고리즘 자동 비교가 미완성이면 모든 확장을 보류한다.
- 배치가 8시간을 넘으면 원인과 반복 단위 중복을 확인한 뒤 지도·seed 규모를 사전 정의하여 축소한다.
- OCI 회수·미확보 시 코드·설정·결과를 복원 가능한 저장소에서 재구축하고 측정 환경 변경을 기록한다.
- 개인키·토큰을 커밋하지 않는다. 큰 영상과 로그는 적합한 별도 저장소/릴리스 자산으로 관리한다.

## 11. 발표와 데모

1. 연구 질문과 차량 운동학 제약 설명
2. 동일 지도에서 세 planner 경로와 실제 추종을 나란히 표시
3. 계획 시간·탐색량·길이와 도달률·충돌·RMSE 비교
4. 대표 실패 사례와 원인 해석
5. 수행했다면 비용함수 확장 및 ablation 결과 제시
6. 작은 demo scenario의 재현 명령 실행
7. 한계 및 부분 미지 환경·PID·모방학습 후속 연구 설명

데모는 작은 시나리오를 사용하고 사전 녹화도 준비한다. 확인되지 않은 예상 성공·실패 장면을 연구 결론으로 제시하지 않는다.

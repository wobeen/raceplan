# 선택적 재출발·재계획 정책

## v2 구현 및 1회 일괄 검증 완료

`RecoveryConfig()`는 이제 v2이며 `policy_version=1`은 기존 회복 제어를 보존한다.
회복을 전달하지 않는 기본 동작은 동일하다. 2026-10-13의 아래 기존 결과는 v1 결과다.
runner의 기존 기본 `baseline/guard/recovery` 모드는 recovery에 명시적으로 v1을
사용하므로 historical 비교를 유지한다. 새 비교는 `--compare-v2`로 요청한다.

- 재계획 시 막힌 활성 경로의 현재 위치 부근 앞 2m를 0.1m 간격으로 저장한다.
  새 후보의 동일 구간이 표본별 0.1m 이내로 같으면 `repeated_blocked_path`로 종료한다.
  다른 후보는 현재 true pose에서 새 Pure Pursuit/PID, 기존 guard, bicycle와 creep를
  사용한 5초의 별도 무노이즈 rollout으로 검사한다. 충돌·재정지 실패가 없어야 하고
  위치 도달 또는 경로 진행도와 순변위 모두 0.5m 이상이어야 적용한다.
  거부는 `recovery_failed/replan_not_trackable`이며 planner 실패와 구분한다.
  실제 state와 실제 난수 스트림은 변경하지 않는다. 검사 wall time은
  `replan_validation_time_s`로 planner wall time과 별도 기록한다.
- creep에서 기본 guard 속도 상한이 creep 속도+0.15m/s 이상(목표/최대속도로 제한)이고
  creep 전방 예측도 안전한 상태가 연속 0.75초 지속되면 `resume` 이벤트와 함께
  일반 tracker+guard로 복귀한다. 진입은 기존 정지 dwell을 그대로 사용한다.
- 회복 이후 watchdog은 목표 직선거리 대신 활성 polyline의 연속적인 국소 투영을
  사용한다. 6초 안에 진행도와 anchor 대비 실제 순변위 모두 0.25m 이상이어야 한다.
  투영 후보는 cursor 인근으로 제한하고 투영 증가량은 실제 이동량 이하로 제한한다.
  따라서 목표에서 멀어지는 정상 우회는 허용하며 교차점 점프·왕복은 진전으로
  누적하지 않는다. 재계획마다 진행 anchor를 초기화하고 총 횟수 제한은 유지한다.

고정 초기 설정을 사용하며 구현 중에는 테스트/실험을 실행하지 않았다. Astra가
정적 검토 후 아래 명령을 각각 1회 실행했다. pytest 71 passed, 비교 144건 완료.
상세 검증 결과는 문서 마지막 v2 검증 절을 참고한다. runner는 저장 첫 경로와 seeds를 공유하고
기존 결과를 읽기만 하며 새 출력 폴더가 이미 있으면 중단한다.

```powershell
.venv/Scripts/python.exe -m pytest -q
.venv/Scripts/python.exe results/recovery_comparison.py --compare-v2 --output results/analysis/recovery_v2_20261013
```

v1 비교는 과거 `recovery_20261013/trajectories.json`과 모든 sample·종료 결과를 대조해야
한다. v2 비교는 8 cases × 3 seeds × 3 planners × 2 조건 = 144건이다. 검사는 전체
경로 안전성 보장이 아니며 실제 noise를 검사 rollout에 적용하지 않는다. 검사에는
v2 속도 복귀를 포함하고 재계획을 금지하여 재귀를 막는다. 검사 episode의 watchdog
시간 제한은 preview보다 길게 설정하므로 검사 중 watchdog은 발동하지 않는다.
대신 종료 시 경로 진행도와 순변위 조건을 별도로 확인한다.
5초 이후 막힘이나 약간 다른 동일 경로를 놓칠 수 있다. 복잡한 교차/자기 중첩 경로의
진행도는 휴리스틱이고, 큰 경로 이탈은 진전으로 인정하지 않아 보수적으로 실패할 수
있다. 불가능 후보에 대해 대안 planner 탐색을 추가하지 않고 즉시 회복 실패한다.
validation 재사용 진단이며 새 held-out 일반화 검증은 별도 필요하다.

기존 guard는 그대로 유지하고 `run_episode(..., obstacle_guard=..., recovery=RecoveryConfig(), replanner=callback)`에서만 회복을 활성화한다. 기본 CLI 및 기존 호출에는 적용하지 않는다. 성공은 기존과 동일하게 충돌 검사 후 목표 위치 0.5m 이내 진입이며 yaw는 제외한다.

## 동작

1. 속도 0.03m/s 이하이며 guard 적용 가속도가 0 이하인 상태가 0.5초 지속되면 재출발을 검토한다.
2. 실제 적용되는 noisy 조향으로 전방 bicycle arc를 예측한다. 최소 0.35m, 또는 후보 속도의 한 제어간격 이동량+제동거리+guard margin+표본간격 중 큰 거리를 검사한다. 모든 표본에서 전체 몸체 충돌이 없고 clearance 0.02m 이상이면 최대 0.25m/s의 저속 주행으로 측면 상한을 대체한다. 매 제어 step 다시 검사한다. 이는 측면 벽과 나란히 진행할 때에만 제한을 완화할 수 있게 한다.
3. 저속 회복 중 전방 예측이 막히면 최대 감속으로 정지한 뒤 재계획을 요청한다. 저속 정지 dwell 후 재출발이 불가능하거나 재출발 예산을 소진해도 재계획을 요청한다. 회복 시작 이후 6초간 목표 거리가 0.25m 감소하지 않아도 재계획을 요청한다. 움직여도 목표 진전이 없으면 반복 운전을 제한한다.
4. 재계획 전 속도를 완전히 0으로 만든다. callback에는 현재 true pose와 기존 목표를 전달한다. 새 경로는 tracker와 PID를 새로 생성하여 사용하며 차량 위치는 변경하지 않는다. 그 제어 step은 정지하고 다음 step에서 새 tracker를 사용한다.
5. 총 재출발 8회, 총 재계획 3회로 제한한다. callback 부재나 재계획 예산 소진은 `recovery_failed`, planner의 no_path/invalid pose/timeout은 `planning_failed`로 종료한다. 전체 주행시간 한도에 먼저 닿으면 `timeout`이다. 어떤 정지나 회복 실패도 성공으로 집계하지 않는다.

설정값은 validation 결과를 보고 반복 튜닝하지 않은 초기 정책이다. true pose와 완전한 정적 지도를 사용하며, 표본 사이 swept collision·동적 장애물·센서/지도 오류·실제 조향/제동 지연에 대한 안전 보장은 없다. Pure Pursuit는 전진 전용이므로 재계획 callback 역시 전진 전용 경로를 제공해야 한다. runner의 Hybrid A* 기본값은 reverse를 사용하지 않는다. callback의 예외는 숨기지 않고 실행 오류로 전파한다.

## 동일 조건 비교

`results/recovery_comparison.py`는 기존 `obstacle_guard_20261013`의 `manifest.json`과 `paths.json`을 읽는다. 첫 경로를 다시 계획하지 않고 baseline/guard/recovery 모두 동일 저장 경로·초기 pose·tracker·노이즈 설정·seed로 실행한다. 회복 조건에서만 필요할 때 같은 planner/설정/계획 지도로 재계획한다. grid planner는 차량 외접원 inflation 지도, Hybrid A*는 물리 지도를 사용한다.

출력 폴더가 이미 있으면 중단하며 원본 자료는 읽기만 한다. 입력 및 실행 소스 hash, 설정, 저장 초기 경로, 에피소드, 모든 궤적과 회복 이벤트/재계획 경로를 기록한다. `comparison.png`와 플래너별 전체 case/seed 궤적 PNG를 만든다. 결과 이미지는 실행 이후에 생성된다.

지표는 성공·충돌·timeout·계획 실패·회복 실패, 시뮬레이션 총 시간/주행시간/정지시간, 재출발/재계획 횟수, 재계획 wall time이다. 정지시간은 각 실제 실행 step 시작 속도 ≤0.03m/s인 구간의 dt 합이며 주행시간은 총 시간에서 이를 뺀 값이다. planner wall time은 시뮬레이션 시간을 진행시키지 않으며 별도 기록한다. 초기 경로가 없으면 초기 계획 실패로 집계하고 회복 planner 실패와 stage 필드로 구분한다. 초기 계획은 재실행하지 않으므로 그 wall time은 이 비교에 포함하지 않는다.

기존 validation을 재사용하는 진단이다. 새 held-out 일반화 평가가 아니며 과거 evaluation split을 새 검증으로 부르지 않는다.

## 검증 범위와 다음 설계 판단

추가 3개 테스트는 측면 벽 저속 재출발, 정지 현재 pose 재계획, planner 실패와
횟수 제한 종료를 확인한다. 이 비교에서 재계획 성공에 의한 실제 회복이나
진전 watchdog의 모든 분기를 검증한 것은 아니다. 새 지도의 일반화·안전 보장도 아니다.

다음 구현 후보는 다음과 같다. 이번 결과를 보고 정책을 재튜닝하거나 재실행하지 않았다.

- 먼저 planner가 반환한 경로의 초기 구간을 현재 tracker와 guard로 실제 진행 가능한지
  확인하는 정책이 필요하다. 거의 같은 pose에서 비슷한 경로를 재계획해도 27회 모두
  진행을 회복하지 못했다. 단순히 재계획 횟수를 늘릴 근거는 없다.
- 충분한 여유가 일정 시간 유지되면 creep에서 정상 속도로 복귀하는 명시적 상태 전환과
  hysteresis를 검토한다. 현재 장시간 저속 운전의 성능 비용을 줄이기 위한 별도 과제다.
- 목표 직선거리만 보는 6초 watchdog은 목표에서 잠시 멀어져야 하는 우회를 실패로
  판단할 수 있다. 활성 경로 진행도와 공간적 진전을 함께 보고, 재계획별 반복을 제한하는
  방식이 적합하다. 현재는 회복 이후 정상 운전에도 이 watchdog이 계속 적용된다.
- 이 validation을 계속 튜닝 데이터로 재사용하지 말고, 다음 정책을 먼저 고정한 뒤
  새 held-out 지도의 도달·충돌·실패·시간을 함께 평가한다.

Hybrid의 **같은 성공 15건** 평균 도달시간은 **15.7367→11.8467초**로 3.89초,
**24.7% 단축**되었다. gate 6건은 동일, turn 6건은 22.25~22.65→17.05~17.25초,
heading q0 3건은 20.75~20.80→11.90~11.95초다. 총 resume 15회가 기록되었고,
turn 각 episode는 재출발/복귀 2회, heading q0는 1회였다. 따라서 v2는 계속 creep로
가는 v1보다 빠르지만, turn에서는 정상속도로 복귀한 뒤 다시 정지/creep에 들어가는
비용이 남는다. 이전 baseline 동일 성공 15건의 7.51초보다는 여전히 느리다.

Hybrid 재계획 횟수는 **27→9회**다. v2 planner 결과 9회는 모두 success지만,
후보 1회는 `repeated_blocked_path`, 8회는 `replan_not_trackable`로 거부되었다.
**적용된 재계획 후보는 0개이며, 재계획으로 도달을 복구한 사례도 0개**다.
후보 거부는 불필요한 재계획 반복을 줄였다는 증거이며 실제 경로 회복의 증거는 아니다.
같은 실패 9건 평균 종료시간은 4.6389→2.6889초로 빨라졌다. 이 차이는 조기 실패
선언이므로 성공 도달시간 개선에 합치지 않는다. Hybrid 전체 24건 주행/정지 평균
10.3813/1.1938→7.8125/0.6000초에도 이 조기 종료 효과가 섞인다.

이번 실행 planner wall time 합은 v1 약 1.1861초, v2 약 0.3959초이고 v2 검사 wall
time은 약 0.0499초다. 하드웨어/실행 부하 영향을 받는 단일 측정이며 시뮬레이션
도달시간과 별개다. 비교 표 및 세 planner 전체 case/seed 궤적 PNG **4장 시각검토**를
완료했다. 글자·범례·장애물·궤적이 표시되고 모든 case/seed가 포함된다. 그림의
전체 평균시간만으로 성공 성능을 판단하지 말고 위 쌍별 성공시간을 함께 사용한다.

### 검증 한계와 다음 설계 의견

- 3개 추가 테스트로 국소 경로 진행도/왕복 및 경로 표본밀도 불변 비교, 지속 여유 후
  정상속도 복귀, 막힌 후보 preview 거부를 확인했다. 전체 episode의 우회 watchdog
  종료 분기와 후보 수락 후 실제 도달은 이번 비교에서 입증하지 않았다.
- preview는 true pose, 무노이즈, 5초 prefix이며 검사 episode는 재출발 1회만 허용한다.
  실제 episode의 남은 재출발 예산과 같지 않아 보수적으로 거부할 수 있다. 검사 내부
  watchdog은 발동하지 않게 설정되어 있고 종료 시 진행도/순변위를 확인한다. 따라서
  전체 noisy 실행의 도달/안전을 증명하는 검사가 아니다.
- 반복 경로 비교는 앞 2m 표본의 위치만 비교하며 yaw/곡률 차이를 직접 비교하지 않는다.
  교차점·자기중첩에서 nearest suffix 선택과 국소 progress cursor는 휴리스틱이다.
  watchdog 개선의 취지는 타당하나 이번 validation에서는 실질 효과를 분리할 수 없다.
- 다음 설계 우선순위는 거부된 후보와 다른 실제 추종 가능 경로를 생성하는 것이다.
  tracker/guard가 요구하는 여유와 곡률을 planner의 후보 생성·선택에 반영하고, 통과하는
  후보를 선택한 뒤 실제 도달을 평가해야 한다. 같은 planner의 재호출 횟수 확대만으로는
  현재 9개 실패를 해결할 근거가 없다.
- 다음 검증에서는 파라미터를 먼저 고정하고 새 held-out 지도에 우회·교차·반복 정지·
  후보 수락 사례를 포함한다. 실제 성공/충돌/실패와 같은 성공 쌍의 시간, 검사 수락 후
  성공률, false rejection 가능성을 함께 본다. 이번 validation에 대한 재튜닝은 하지 않았다.
